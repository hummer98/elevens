補足が必要なモデル

  • GPT-5系 (OpenAI) — 動画系ベンチマーク性能は謳われるが、API はフレーム抽出+Whisper書き起こしの分解方式。Realtime API も画像まで。
  • Claude (Anthropic) — Fable 5 / Opus 4.8 含め動画入力非対応(画像・PDFまで)。ffmpeg でフレーム抽出して画像として渡すワークアラウンドになる。
  • Sora 2 (OpenAI) — 動画「生成」モデルで解析用途ではない。Videos API は 2026-09-24 廃止予定。

用途別推奨

  • 手軽に API で動画解析 → Gemini 2.5 Flash(コスト)/ Gemini 3 Pro(精度)
  • 長尺動画・放送/メディア業務 → TwelveLabs Pegasus 1.5
  • ローカル/セルフホスト → Qwen3-VL

ローカルLLMの生成速度はほぼメモリ帯域で決まる。M4 Pro は帯域・MLX最適化の両面で Orin の実測4〜5倍。無印 M4 は 32GB 上限・120GB/s のため 30B クラス前提なら M4 Pro 一択。

推奨の進め方

  1. まず Jetson で試す(追加コストゼロ) — 20〜30 tok/s はバッチ用途なら実用。64GB あるので長コンテキストに有利。注: cuda-toolkit (nvcc) 未導入、必要なら sudo apt install nvidia-jetpack。
  2. 対話的に使う・速度が欲しい → M4 Pro 64GB 購入 — MLX-VLM が Qwen3-VL 対応。M5 mini を待つ価値は現時点で不確実。
  3. 隠れた選択肢: 自宅 RTX 3090 — 帯域 936GB/s で最速。ただし VRAM 24GB のため AWQ 4bit (約17GB) 限定で、動画解析の長コンテキストでは KV キャッシュが厳しい。短尺クリップ解析なら最速環境。

3. RTX 3090 (24GB) で動かすコーディング向けローカルLLM

目標: Claude Code (Fable 5) / Codex 5.5 級とはいかなくても、現実的なトークン速度で実装タスクに使えるローカルLLM。

Claude Code との接続 (2026年現在の最短経路)

2026-01-16 に Ollama、2026-01-30 に LM Studio が Anthropic Messages API 互換エンドポイントを実装。プロキシ不要で Claude Code を直結できる。

# Ollama (bazzite 側で稼働) に Claude Code を向ける
export ANTHROPIC_BASE_URL=http://172.25.76.145:11434
export ANTHROPIC_MODEL=qwen3.5:35b-a3b
claude
  • コンテキスト長が肝: ローカルで Claude Code 的に使うなら 64K が実用ライン(32K未満はチャットデモ)。35B-A3B Q4 は VRAM 約20GB消費 → KVキャッシュ q8 量子化で 64K を確保するのが定石。
  • スループット重視なら vLLM (AWQ) + LiteLLM プロキシ構成。
  • Claude Code 以外では OpenCode / Qwen Code CLI がローカルモデルとの相性が良い定番。

期待値の設定

  • Fable 5 / Codex 5.5 との差は「一発で正しい設計判断をする能力」と「長時間の自律実行」。ローカル勢は明確な仕様を渡した実装・リファクタ・テスト書きなら実用、曖昧な指示からの長距離エージェント実行は厳しい(2026年中盤の相場)。
  • 112 tok/s あれば体感はクラウド API と遜色なし。プレフィルも 3090 なら十分。
  • 注意: Ampere + A3B MoE では llama.cpp の投機的デコードは全構成で逆効果という検証結果あり。チューニングに時間を使わない。

次のアクション案

  1. bazzite に Ollama 導入(immutable OS のためコンテナ or brew 経由)
  2. Qwen3.5-35B-A3B 4bit を pull、KVキャッシュ q8 で 64K コンテキスト構成
  3. Mac から ANTHROPIC_BASE_URL を向けて Claude Code で実タスク評価
  4. 精度不足を感じたら Qwen3-Coder-Next ハイブリッドを llama.cpp で検証
